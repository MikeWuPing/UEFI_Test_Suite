AdvDiskTest 硬盘检测工具 - 可启动 ISO
=====================================

这是一张 UEFI 直启盘：固件从它启动后直接进入 AdvDiskTest 主界面，中间不经过
UEFI Shell。界面为简体中文，鼠标与键盘都能操作。

使用方式
1. 虚拟光驱 / 虚拟机：把 ISO 挂成虚拟光驱、排在启动顺序第一位。（服务器 BMC /
   远端管理口的"挂虚拟光驱 + 强制启动项"是同一类做法。）
2. U 盘：按下面任一种写法制作——
   * Rufus 的默认写法（"ISO 模式"）：盘内文件被解到 U 盘的 FAT32 分区，固件按
     常规路径找到 EFI/BOOT/BOOTX64.EFI；
   * Rufus 的"DD 镜像模式"，或 balenaEtcher / dd：整个 ISO 按字节写进 U 盘，固件
     从 El Torito 引导项进（那张盘上内嵌的 5 MB FAT16 映像）；
   * 拷贝方案：把 ISO 放进 Ventoy 分区，开机在 Ventoy 菜单里选第一个菜单项（正常
     模式）。盘内另带一份 EFI/BOOT/grub.cfg，供 Ventoy 的"grub2 模式"兜底使用。
3. 刻盘：刻到 CD/DVD 上，用 UEFI 固件从这张光盘启动。

上面三条里，**本版实测过的是"虚拟光驱"与"整盘按字节写入的块盘"这两条链路**。
也就是说：**Rufus"ISO 模式"、Ventoy、实体刻盘，
以及在真实硬件上启动（含服务器 BMC 的虚拟光驱与真机上的 U 盘），
本版都没有实测**——它们按标准 UEFI 启动流程给出，不是对本盘的量测。

Secure Boot 要先关掉：本程序没有微软签名，开着 Secure Boot 的机器不会放行这张盘；
测试做完可以再打开。
老式 BIOS / CSM 启动不支持：这张盘的引导目录里只有一个 UEFI 条目（没有 BIOS
条目），启动时机器必须处在 UEFI 模式。
界面要用图形控制台（UEFI GOP/VGA）显示；串口那边只有日志、没有画面。

目录内容
  EFI/BOOT/BOOTX64.EFI   AdvDiskTest 本体。光驱 / 虚拟光驱链路上，固件是从盘内的
                         文件系统树里读它并直接执行的。
  EFI/BOOT/grub.cfg      GRUB 兜底配置：Ventoy"grub2 模式"交棒时用它 chainload
                         上面那一份。
  ESP_IMG.BIN            5 MB 的 FAT16 映像，里面另装着一份同样的 BOOTX64.EFI；
                         El Torito 引导项指的就是它（把整盘按块设备写进 U 盘时，
                         固件从这里进）。它是盘内接线，不必去挂载。
  README.TXT             盘内英文启动说明（随 ISO 生成）；你现在读的这份中文说明
                         随发布包提供。

介质上会怎样（本版实测）
本节每一条都是本版实测到的，不是推断；每条都附上程序自己打出来的痕迹。1)—3)
在**光驱链路**上做（把本 ISO 挂成虚拟光驱启动）。

1) 报告导不出来——但程序不崩、界面照常。
   HTML 报告要落到一个可写的卷上；只读介质启动时没有这样的卷（唯一挂载得到的
   那个卷是只读的），创建文件被拒（Write Protected）。程序的处理是：在导出屏上
   写清原因
       （只读介质启动）本机没有可写的卷，报告导不出来
   并在串口留一行
       P7RPT: disk=0 failed why=no-volume (Write Protected) file=<候选文件名>
   之后程序照常运行：这一轮里关框、退出都照常响应，串口打出 [AdvDiskTest] exit
   clean，没有崩。要拿到报告，把盘内的 EFI/BOOT/BOOTX64.EFI 拷到可写盘上直接
   运行，或者换一张可写的介质。

2) 外观设置当场生效，但存不住。
   只读介质上切"深色 / 浅色"立即生效；程序会尝试把设置写回配置文件，被拒，串口
   留一行
       CFG: open for write failed (Write Protected), ui.theme=1 not persisted
   重启后回到默认的深色档（实测：从"浅色"切档后重启，串口是 CFG: cfg file not
   found, ui.theme defaults to dark，外观框里勾选的仍是"深色"）。

3) 启动盘保护照常生效。
   本工具不给"自己的启动盘"做写验证（安全设计：写验证会在这块盘上动分区表与引导
   区）。只读介质启动时它同样认得出自己的启动盘——实测容量核验屏上写验证那一栏
   写的是
       目标盘是本机的启动盘，不提供写验证——这一写会落在分区表与引导区上
   串口同时打出 P6PROOF: disk=0 boot=1 how=bio。

4) 同一张 ISO 按"镜像模式"写进 U 盘之后，盘不再是只读的。
   此时走的是**块盘链路**（把 ISO 原样写进一块盘、让固件从它启动）：
   固件走盘内 El Torito 引导项，其中内嵌的 FAT16 段是一个可写的卷（实测：它是
   这条链路上唯一的文件系统卷），程序启动时会把记录写上去（实测 DISK: fs
   handles=1 wrote handle[0] bytes=868 (Success)）。要清掉它，重写一次 U 盘即可。

其他实测
* 界面上的"退出"不会让机器断电：控制权交回固件（本机实测是固件转去启动它自带的
  启动管理菜单），也没有紧接着又把这盘起一遍。要结束测试就手动关机、下次改选别的
  启动设备，或者把盘取下来。
* 按"DD 镜像模式"写入的 U 盘要改回普通 U 盘，用磁盘工具重新分区格式化即可。
