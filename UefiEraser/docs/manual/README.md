[README.md](../../README.md)。

## 1. 这是什么

UefiEraser 是运行在 **UEFI Shell**（操作系统启动之前的环境）里的磁盘数据粉碎工具。
它把整块物理磁盘、单个分区、或分区的空闲空间用行业标准的多遍覆写彻底抹掉，
也可以让磁盘固件自己执行 ATA Secure Erase / NVMe Format / Sanitize。

**擦除之后数据不可恢复。**

为什么要在 UEFI 下做，而不是在 Windows 里跑一个擦除软件：

- 系统盘（装了正在运行的操作系统的那块盘）在 Windows 里无法整体擦除；
  在 UEFI Shell 里没有任何文件被占用。
- 不依赖任何操作系统，一块 U 盘就能在任何机器上开工。
- 目标列表直接从固件枚举，看到的就是固件看到的物理设备，没有盘符/挂载点的误导。

## 2. 适用与不适用

| 介质 | 建议方式 | 原因 |
|---|---|---|
| 机械硬盘（HDD） | 多遍覆写（分区/整盘） | 写入落在确定的物理扇区上，覆写即覆盖 |
| 固态硬盘（SSD / NVMe） | **设备级擦除（Pro 版）** | FTL 与磨损均衡会把写入重映射到别的物理块，覆写逻辑地址**不能保证**覆盖原数据 |
| U 盘 / SD 卡 | 不推荐任何方式 | 同上，且控制器行为不透明；物理销毁更可靠 |

> **多遍覆写对 SSD 不可靠，这不是本工具的限制，是 SSD 的工作原理。**
> 设备级擦除属于 **Pro 版**。在 Free 版里它就写在「算法…」对话框下方：
> **灰显加锁**，点它会说明属于哪个版本，在当前版本不会执行任何写盘动作；
> 具体用法见 [§17](#17-pro-版功能free-版不含)。

## 3. 开始之前

1. **准备启动盘**：把 `UefiEraser.efi` 拷到一个 FAT/FAT32 格式的 U 盘或 ESP 分区根目录。
   （UEFI Shell 认 FAT，不认 NTFS/exFAT。）
2. **进入 UEFI Shell**：开机时进固件设置，选择从该 U 盘启动，或选择
   "UEFI Shell" 启动项。部分主板需要在 BIOS 里打开 "Launch UEFI Shell from
   filesystem device"。
3. **切到对应卷**：

   ```
   Shell> fs0:
   FS0:\> UefiEraser.efi
   ```

   不确定盘符就用 `map` 列出所有卷，找 `FS0:`、`FS1:` 里带 `VenHw` /
   `SATA` / `NVMe` 描述的那一栏。

4. **确认目标**：界面里每块盘都会显示容量与型号/路径，**擦之前务必核对容量**。
   同一块盘上可能有多个分区，别只看序号。

> 断电 = 灾难。擦除过程中请确保电源稳定（笔记本接电源适配器），
> 不要按复位键。覆写中途断电会留下**部分覆写**的介质：数据不完整，但也没擦干净。

**选不中的行**（**整行置灰**，第二行小字直接写明原因）：

- 这些行画成**灰色、方括号里是 `-` 而不是复选框**，第二行末尾附上原因，
  例如 `64 MB  MBR  3 个分区  当前启动卷  （本程序正在运行于此盘，不可选）`。
- 点这些行时，列表下方的**提示条**会再说明一次并记入串口日志；
  「全选」也会报告"跳过了几个、为什么"。
- **只读**设备（写保护的光盘、只读介质、`Media->ReadOnly`）完全不可选。
- **当前启动卷**及其所在的整盘不可选——本程序正是从那里加载的，
  擦掉它等于在运行中自毁。同一块盘上的**其它分区仍然可以擦**。
- **可移除**介质只做提示，不阻止（U 盘本身也是合法目标）。

## 6. 选择擦除方式与算法

点「算法…」（或按 F5）打开选择器。这是一个接近整屏的大对话框（1180×720），
  列表分两段，**表头写明总数**（"共 30 种（含 Pro 版 18 种）"）：

- **上半部分：本版本可用的 12 种覆写算法**（单选）。每行只写名称与遍数——Gutmann
  的 35 遍写成一行是噪声，遍序挪到了悬停提示里；
- **下半部分：标准扩展算法名录（Pro 版）**，18 种，**灰显 + 锁 + 右侧标注发布机构**
  （国家保密局 BMB21-2019、强制性国标 GB 46864-2025、公安部 GA/T 1143-2014，以及
  CSEC ITSG-06、NAVSO P-5239-26、NCSC-TG-025、BSI-2011-VS、ACSI-33、ISM 6.2.92、
  NNSA NAP 15.1-C、AFSSI 8580、DoD 全 7 遍、零填充、全 1 填充、只读校验、自定义遍序
  编辑）。**点它会说明这属于 Pro 版**，在当前版本不会执行任何写盘动作。

**列表比窗口长，所以三处都在提示下面还有内容**：右侧一条常显滚动条、列表右下角的
向下箭头（上面还有内容时会出现向上的箭头）、列表下方一行文字"下面还有 N 项，可滚动
或按 Tab 查看"。用 Tab 移动焦点时列表会**自动滚动**，焦点行永远可见。

**鼠标悬停在任意算法行上**会弹出该算法的说明框：它的来历、适用场合，以及完整遍序
（长遍序按 token 截断并注明总数，完整表见 §11）。

![算法选择器](images/05-algorithm.png)

![悬停查看算法大意与遍序](images/05c-algorithm-tooltip.png)

![列表下半部分：Pro 版算法名录](images/05d-algorithm-pro-roster.png)

- **读回校验末遍**：打开后，最后一遍写完会把整段数据读回来，与该遍生成器的
  重放结果逐字节比对。速度大约减半，但能发现"写了但其实没落盘"的情况。
- **自定义遍数**：在算法对话框里按 `+` / `-` 调整（1~64），只对「自定义（随机
  N 遍）」生效。

**算法为什么不能多选**：擦除算法就是**一次运行的遍次序列**。同一段落盘字节上
"既是 Gutmann 又是 DoD"没有意义——后一遍会覆盖前一遍，最后留下的只有最后一遍。
所以一次运行只允许一种算法；需要更多遍请用「自定义（随机 N 遍）」。
同类工具也都是单方法：Eraser 每个任务一个 method，DBAN 每次运行一个 method，
Blancoo / `shred` / `sdelete` 亦然——"多"在**方法内部的遍数**里，不是并行多个方法。
（遍历次模式见 §11。）

设备级擦除三选一（**Pro 版**；Free 版里这三项灰显加锁，点它会给出版本说明）：

- **ATA Secure Erase** —— 走 ATA SECURITY ERASE UNIT，机械盘与 SATA SSD 适用。
- **NVMe Format NVM** —— NVMe 的 Format NVM（SES=用户数据擦除）。
- **NVMe Sanitize** —— NVMe Sanitize（块擦除），覆盖面最广。

设备级擦除**只能用于整盘**：如果选中的目标里有分区，程序会直接拒绝不会执行。
设备能力不支持时（例如盘处于 Frozen 状态、或固件不实现该命令）程序会**明确报错**，
不会静默退化成覆写。

## 7. 确认闸门

从「开始擦除…」到真正写盘要经过四道闸门（选中整盘时是五道），
设计原则是：**按钮可以手滑点下去，输入框不行。**

1. **摘要确认** —— 列出目标数量、其中整盘几个、待写入总量、算法与遍数，
   并把选中的目标逐个按名字列出来。请核对这一屏的数字和名字。
2. **输入 `ERASE`** —— 全大写输入（小写会自动转成大写）。
3. **输入整盘容量** —— 若选中了整盘，还要再输入这些盘的容量合计（GiB）。
   这一步是逼你真的去看一眼容量。
4. **运行中可取消** —— 进度对话框上的「取消」按钮。

任何一步按 Esc 或点「取消」都会中止，不会写任何数据。

- **容量数字用哪个单位**：整盘容量合计 **≥ 1 GiB 时按 GiB** 提问（例如 250 GB 盘要输 `250`）；
  **不足 1 GiB 时按 MiB**（例如 512 MiB 盘要输 `512`）。以前一律用整数 GiB，小盘永远问
  "请输入 0"——那就不是一道确认了。
**输入类的闸门不会"默默不理你"**：输入框下方有实时提示行——输入正确时变绿
（`输入匹配 —— 可以按「确认擦除」了`），输入错误时按确认会同时做三件事：
提示行变红说明差在哪、弹出一个说明"该输入什么"的对话框、串口日志记一行
`[Ui] gate N refused`。空输入会明确告诉你"输入框还是空的"。

![空输入直接按确认：弹窗说明该输入什么](images/07b-gate-empty-notice.png)

![输入匹配后提示行变绿](images/07d-gate-typed.png)

## 8. 执行与取消

进度对话框显示：第几个目标 / 共几个、**当前遍次 / 总遍次**、百分比、速率、
剩余秒数，以及一条「请勿断电」。对话框**在擦除期间持续刷新**（玻璃层会自动关掉，
让重绘从进度卡开始、不去碰壁纸），所以进度条是真的在走：

![擦除进度（可取消）](images/09-progress.png)

| 数秒之后：进度条在推进 | 擦完直接出结果报告 |
|---|---|
| ![进度推进](images/09b-progress-later.png) | ![结果报告](images/10-report.png) |

- 取消是**协作式**的：引擎在每个数据块之间检查取消标志，因此会在几百毫秒内
  停下，而不是立刻。
- 取消之后，已经写过的部分**无法还原**——目标处于"部分覆写"状态，
  既不是原数据，也没擦干净。报告里会明确标记 `已取消`。
- 每个目标擦完就写一条审计日志，所以中途取消时，已完成的部分仍然有据可查。

## 9. 结果与导出

擦完弹出结果对话框：

| 显示 | 含义 |
|---|---|
| 擦除完成（绿） | 全部目标成功 |
| 擦除完成，但末遍读回校验未通过（黄） | 写完了，但读回来的字节与预期不一致，需要重跑 |
| 已取消 —— 目标可能未完全清除（黄） | 用户中断，见上 |
| 擦除失败: <原因>（红） | I/O 错误 / 参数错误 / 介质变更等 |

点「**导出报告**」（或按 **F2**）把同一份结果写成 `UefiEraser-report.txt` 放到启动卷
根目录（UTF-8 文本，每次运行覆盖上一次）。**导出后会弹出结果对话框**：成功时显示
「已写入启动卷：UefiEraser-report.txt」，失败时说明"启动卷不可写（写保护或只读状态）"
并提示检查写保护开关。关掉弹窗就回到结果对话框，可以再导出或关闭。
导出失败绝不影响擦除本身。

![导出成功后弹出的结果对话框](images/10b-export-notice.png)

## 10. 四种典型流程

### 整盘粉碎（换机前清盘）

1. 选中列表里的**磁盘节点**（不是下面的分区）。
2. 「算法…」→ 选一个算法（机械盘推荐 DoD 5220.22-M；SSD 请改用设备级擦除）。
3. 「开始擦除…」→ 核对摘要 → 输入 `ERASE` → 输入容量数字。
   设备级擦除（ATA Secure Erase / NVMe Format / NVMe Sanitize）由**盘自己的固件**执行，
   需要盘支持该命令；不支持时报告对话框会直接写出原因，不会含糊地只说"I/O 错误"。
4. 等进度走完 → 看结果 → 可选导出报告。
5. **目标列表会自动重扫**，而且是**按介质本身的内容**重扫的：应用会重新读一遍每块盘的
   分区表（LBA 0），**介质上已经不存在的分区行会被直接丢掉**。所以刚被擦掉分区的盘在列表里
   就不再显示子分区，那一行的第二句也会从 `GPT 3 个分区` 变成 `无分区表`。
   也可以随时用 `操作 → 重新扫描目标` 手动重扫（换了盘、插了新盘都适用，重扫结果会在
   下方的提示条里报出目标数与被丢弃的分区行数）。

> 为什么不用 `reconnect -r` 那种"让固件自己重连"的做法？实现过、在 OVMF 上也能成功，
> 但它的代价是**停掉再启动每块盘的驱动**：驱动一旦没起来，那块盘就会从列表里消失到重启
> 为止——而这正是擦除工具最不该有的失败方式。按介质重读既不需要动固件，得到的结果又和
> 用户能亲自核对的东西（盘上的字节）一致。

> 整盘擦除会连分区表一起抹掉，之后这块盘在本应用里就显示为 `无分区表`（固件侧同样视作
> 未初始化磁盘），可见的只剩它自己这一行。

### 分区粉碎（只清一个分区）

同上，但选中**分区节点**。边界是精确的：相邻分区逐字节不受影响
（这一条由 `tools/Verify-Erased.py` 的字节级断言证明）。

### 空闲空间粉碎（保留现有文件）

选中分区 → 「算法…」选擦除方式时选「空闲空间」类目标（列表里的
「空闲空间」子项）。这一步会**在卷根反复创建临时文件、按算法模式写满、再删除**，
把未使用的簇覆盖一遍，从而消除已删除文件的残留；**现有文件保持完好**。

卷快写满时视为该遍成功（写不动说明没空间了，没空间就没有残留）。
结束后不应留下任何临时文件——`tools/Verify-FreeSpace.py` 会断言这一点。

### 设备级擦除（Pro 版，SSD 唯一可靠方式）

1. 选中**整盘**节点（分区会被拒绝）。
2. 「算法…」→ 下半部分选 ATA Secure Erase / NVMe Format / NVMe Sanitize。
3. 「开始擦除…」→ 核对 → `ERASE` → 容量。
4. 固件在后台执行，主机拿不到逐遍进度，界面只显示"进行中…请勿断电"。

## 11. 算法遍次表

`R` = 伪随机数据流；`R1/R2/R3` = 每次擦除抽一个随机字节后整遍重复；
`~R1` = `R1` 的按位取反；其余为常量字节（多字节模式在缓冲区内循环）。

| id | 名称 | 遍数 | 遍次模式 |
|---|---|---:|---|
| `dod522022m` | 美国国防部 DoD 5220.22-M | 3 | 00, FF, R |
| `dod522022m_ece` | DoD 5220.22-M (ECE) | 7 | R1, ~R1, R, R2, R3, ~R3, R |
| `gutmann` | Gutmann | 35 | 4×R；55；AA；92 49 24；49 24 92；24 92 49；00,11,22,33,44,55,66,77,88,99,AA,BB,CC,DD,EE,FF；92 49 24；49 24 92；24 92 49；6D B6 DB；B6 DB 6D；DB 6D B6；4×R |
| `schneier` | Schneier | 7 | 01, 00, 5×R |
| `hmg_is5_baseline` | 英国 HMG IS5（基础） | 1 | 00 |
| `hmg_is5_enhanced` | 英国 HMG IS5（增强） | 3 | 00, 01, R |
| `rcmp_tssit_ops2` | 加拿大 RCMP TSSIT OPS-II | 7 | 00,01,00,01,00,01, R1 |
| `vsitr` | 德国 VSITR | 7 | 00,01,00,01,00,01, R |
| `gost_p50739` | 俄罗斯 GOST P50739-95 | 2 | 00, R |
| `ar380_19` | 美国陆军 AR 380-19 | 3 | R, R1, ~R1 |
| `usaf_5020` | 美国空军 5020 | 3 | R1, R2, R3 |
| `custom` | 自定义（随机 N 遍） | N | N × R |

遍次模式**逐字节对照 Eraser 源码**确认（快照见 `docs/reference/eraser/`）。
有几处与常见文献不同，本工具按 Eraser 的字节值实现：Schneier 用 `01, 00` 起手
（不是 `FF, 00`）；VSITR 与 RCMP 交替用 `01` 而非 `FF`；HMG IS5 增强版第二遍是 `01`。

**一处有意偏离**：Eraser 对 Gutmann 会打乱 35 遍顺序；本工具按 Gutmann 原文的
规范顺序执行，因为那 27 个模式是按序针对特定编码设计的，打乱会破坏算法本意。

## 13. 无界面模式与配置文件

自动化场景可以不进界面：

```
FS0:\> UefiEraser.efi erase=part:0:2 algo=dod522022m verify
```

| 参数 | 说明 |
|---|---|
| `erase=disk:<i>` | 第 i 块整盘（0 起，按枚举顺序） |
| `erase=part:<i>:<n>` | 第 i 块整盘的第 n 个分区 |
| `erase=freespace:<i>:<n>` | 第 i 块整盘第 n 个分区的空闲空间 |
| `erase=ata:<i>` | 对第 i 块盘执行 ATA Secure Erase |
| `erase=nvme-format:<i>:<ses>` | NVMe Format NVM |
| `erase=nvme-sanitize:<i>:<act>` | NVMe Sanitize |
| `algo=<id>` | 算法 id（见 §11，默认 `dod522022m`） |
| `custom=<n>` | 自定义算法遍数 |
| `verify` | 开启末遍回读校验 |

同样的参数可以写进启动卷根目录的 `UefiEraser.cfg`（UTF-16LE 文本），
供无法传命令行参数的引导方式使用。命令行存在时优先于配置文件。

无界面模式下每完成一个目标，同样会写审计日志与 `UefiEraser-report.txt`。

## 14. 安全须知（请读完）

1. **擦除不可逆。** 没有撤销，没有回收站，没有"找回"。
2. **先备份。** 确认该备份的东西在**别的地方**有一份，且那一份能打开。
3. **核对容量。** 界面和确认对话框都显示容量；`1 TB` 和 `128 GB` 在列表里可能
   长得差不多。
4. **SSD 用设备级擦除。** 覆写对固态盘不可靠。
5. **别在擦除时断电。** 见 §3。
6. **日志写在启动卷上。** 如果擦的正是启动卷所在的那块盘，日志会随之一起消失——
   这是预期行为（启动卷本来就不可选）。需要留存请把报告导出到**另一个**卷。
7. **机械盘的坏块重映射**：厂商保留区里退役的坏扇区无法被主机覆写，
   极端情况下可能有极少量残留。**高度敏感场景请用设备级擦除或物理销毁。**
8. **本工具按"尽力而为"写日志**：任何日志/报告写入失败都会被静默忽略，
   绝不阻断擦除本身。所以"没有日志"不等于"没有擦除"。

## 15. 故障排查

| 现象 | 原因与处理 |
|---|---|
| `UefiEraser.efi` 提示命令不存在 | 盘符不对；用 `map` 确认后在正确卷下运行。UEFI Shell 区分大小写吗？不区分，但要带 `.efi` |
| 启动就黑屏/卡住 | 显卡 GOP 分辨率过小（< 800×600 无法布局）；换一台机器或换个固件分辨率设置 |
| 目标列表里看不到某块盘 | 固件没给这块盘 `BlockIo`（例如在 RAID/Intel RST 模式下）；进固件设置把 SATA 模式改成 AHCI |
| 某块盘整盘标了「当前启动卷」且选不中 | 本程序从该盘加载；想擦它请从**别的**卷启动（例如把 efi 放到第二块 U 盘） |
| 「设备级擦除只能用于整盘」 | 设备级命令作用于整个物理设备；取消分区选择，只保留整盘 |
| ATA Secure Erase 报 I/O 错误 | 盘处于 **Frozen** 状态（很多笔记本固件为了防 ransomware 会上冻结锁）。常见解法：让系统进入睡眠再唤醒，冻结锁会解除；或者用支持解锁的机器上做 |
| 设备级擦除失败，报告说 I/O 错误 | 点「关闭」前先看报告里那行橙色文字——它就是原因。四项常见：**不在 ATA 端口下**（QEMU 的 virtio/SCSI 虚拟盘、USB 转接桥都这样）、**盘未实现 ATA Security feature set**、**盘处于 FROZEN**（固件上了冻结锁，需断电重试）、**不在 NVMe 端口下**。算法选择器里也写明了这三项的前置条件 |
| 擦除跑到一半**整机重启**了 | 多半是按了 **Ctrl+Alt+Del**。固件把控制台的这个组合当复位键，而且走的是键盘**通知**通道——应用正在读键盘也拦不住（本轮实测：擦除中发一次 Ctrl+Alt+Del，机器立刻重启，日志里表现为 `BdsDxe: loading Boot0002` 再次出现、`UI up` 再来一次）。要中止擦除请用进度对话框的「取消」 |
| 启动后久等不见界面 / 屏幕是黑的 | 模拟环境（QEMU TCG）下从固件到界面要约 **30–40 秒**，真机会快得多；这段时间的黑屏和固件文字都正常。**千万不要按 Ctrl+Alt+Del**——那会整机重来（实测会反复重启，看起来像卡死） |
| 末遍校验不通过 | 介质存在写入缓存或坏块重映射；换设备级擦除，或换物理销毁 |
| 空闲空间擦除说"卷满" | 这是成功的信号：写不动说明没有可写空间，也就没有残留 |
| 界面出现方框（豆腐块） | 字库缺字；本工程的字库覆盖由 `tools/check_font_gaps.py` 校验，若自行改界面文案需重跑该脚本 |
| 点了目标却选不中 | 该目标不可选（只读设备 / 当前启动卷）；列表下方会弹出提示条说明原因（**一旦选中合法目标，提示条立刻消失**），「全选」也会报告跳过了几个 |
| 擦除后分区行怎么没了，是没擦干净吗？ | 恰恰相反，那是擦干净的证据：重扫会重新读每块盘的分区表，介质上没有表就不再列分区，整盘那行的第二句变成 `无分区表`。想核对可看串口日志：`[Ui] ghost: N partition row(s) dropped ...` 与 `[Ui] refresh: devs=… targets=… ghosts=N` |
| 某块盘的分区行没消失 | 该盘的分区表没被写掉（只擦了部分分区），或分区表的读取失败了——后一种情况第二句会显示 `分区表未知`，此时应用按"看不出来就不动"处理，仍会照常列出固件报告的设备 |
| 发起擦除后画面停在确认对话框 | **0.1.0.63 已修**。原因是擦除跑在 LVGL 的事件回调里，而 `lv_timer_handler()` 有重入保护：整个擦除期间定时器全被拒绝，动画与整屏重绘因此停摆（进度条、百分比、速率都看不见）。现在确认闸门只排队、由主循环执行擦除，进度对话框正常显示并推进。低于 0.1.0.63 的版本才会看到这个现象 |

## 16. 日志与报告字段

`UefiEraser.log`（UTF-8 CSV，追加）：

```
iso_timestamp,target_name,mode,algo,passes,result,bytes_written
2026-09-16T16:43:47,disk:0,overwrite,random,1,OK,67108864
```

| 字段 | 说明 |
|---|---|
| `iso_timestamp` | 擦除结束时刻（来自 RTC；固件时钟没校准时可能不准） |
| `target_name` | `disk:<i>` / `part:<i>:<n>` / `freespace:<i>:<n>` |
| `mode` | `overwrite` / `freespace` / `ata` / `nvme-format` / `nvme-sanitize` |
| `algo` | 算法 id；设备级擦除为 `-` |
| `passes` | 完成遍数；设备级为 `0`（固件执行，主机无遍数概念） |
| `result` | `OK` / `CANCELLED` / `IO_ERROR` / `VERIFY_FAIL` / `PARAM_ERROR` / `MEDIA_CHANGED` |
| `bytes_written` | 主机侧写入字节数；设备级为 `0` |
